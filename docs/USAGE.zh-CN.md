# 使用

[English](USAGE.md) | **简体中文**

自然语言是主要入口。需要精确选择任务或控制服务时，再使用固定命令。

## 创建任务

直接向机器人发送普通私聊消息：

```text
检查最近失败的测试，先只读取，不要修改文件
```

没有当前事项时，普通消息会在识别到的项目或默认范围中新建事项。可以点“交办新事项”明确选择范围。
已有当前事项时，普通补充会先显示“继续这件事 / 另开一件事”；明确的继续指令和引用回复会直接处理。

## 继续任务

最可靠的三种方式：

1. 点卡片上的“继续这件事”，在表单中填写补充；
2. 使用飞书的引用回复功能，回复对应卡片；
3. 发送 `继续1 <消息>`，序号来自最近一次任务列表。

仅点击卡片再发普通消息，不等于引用回复。目标不明确时，原消息会保留，选择后再发送。

回复绑定可以确保消息进入正确的 Codex 任务。已停止、失败或归档的任务会通过 Codex
原生流程恢复或继续。如果另一个 Desktop 进程仍持有当前写入权，后续消息会进入本机
持久化队列，等待写入权释放后只发送一次。

## 查看进度

发送 `任务` 查看最近 5 个任务。点击任务可查看摘要，发送 `详情1` 可查看结构化进展：

- 当前阶段和耗时；
- 计划步骤及状态；
- 工具和 MCP 调用；
- 执行命令；
- 修改文件；
- 可恢复或终止错误。

出于安全考虑，不展示原始 reasoning、完整工具参数和完整终端输出。打开详细进展卡后，
在卡片回调 token 有效期间会原地更新。

## 图片、文件和语音

“继续这件事”表单只填写文字；图片请从机器人私聊的聊天输入框发送。
要补充到已有事项，可以引用回复对应事项卡再发图；也可以先打开该事项、直接发图，
再在确认卡中核对事项名称并选择“继续这件事”。

直接发送图片或文件，可以创建带附件的任务；回复任务卡发送附件，会补充到该任务。
飞书 ASR 权限和 `ffmpeg` 可用时支持短语音转写，当前语音时长上限为 60 秒。

## 页面操作

主操作使用整行大按钮；次要操作每行最多两个；返回入口位于底部。停止、取消和归档保留确认提示。
首页按正在处理、需要查看和最近结果组织事项；技术细节放在折叠区。
“待发送与恢复”按事项组织消息；提交结果不确定时只提供查看入口，不提供直接重试。

## 本机定时任务

首页“筛选与更多”中进入“定时事项”，点击“新增定时事项”即可填写；也支持下列指令。
定时任务运行在 Mac 上，不是云端调度：

```text
定时 每天 09:00 android-main 检查 CI
定时 明天 10:30 memory 汇总进度
定时任务
```

支持一次性、每日和每周表达式。执行时间到达时，Mac 必须保持唤醒，或在配置的补偿窗口内恢复。

## 精确命令

| 命令 | 作用 |
|---|---|
| `任务` / `首页` | 打开任务首页 |
| `新建` | 打开新建任务表单 |
| `进度1` | 查看第 1 个任务摘要 |
| `详情1` / `详细进展1` | 查看第 1 个任务的结构化进展 |
| `继续1 <消息>` | 继续第 1 个任务 |
| `关注1` / `取消关注1` | 管理完成通知 |
| `停止1` | 二次确认后停止当前回合 |
| `归档1` | 归档已完成任务 |
| `队列` | 查看持久化后续消息 |
| `定时任务` | 查看本机定时计划 |
| `静默 2小时` / `恢复通知` | 暂停或恢复通知 |
| `健康` / `版本` / `帮助` | 查看服务状态、版本或帮助 |

序号来自最近一次任务列表或搜索结果。

## 可用性说明

- Mac 必须保持唤醒并联网。
- 断线后 Bridge 会恢复已经收到的事件暂存和持久化消息队列；断线期间未送达的消息不保证自动补回。
- “连接状态”区分监听启动、连接已确认和重连中；最近收到消息的时间不是持续在线保证。
- Mac 关机时无法执行本机定时任务。
- 需要额外权限或人工输入时，必须回到 Codex Desktop 处理。

消息没有回复时，请查看[故障排查](TROUBLESHOOTING.zh-CN.md)。
